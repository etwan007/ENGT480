# Global configuration and shared utilities

All current Python pendulum controllers use this package. The capital `G` is
required on the Pi. Keep this layout when copying to another computer:

```text
Code/
  Global/
    __init__.py
    physical_parameters.py
    run_csv_logger.py
    angle_protocol.py
    angle_packet_fallback.py
    live_offset_keys.py
    AngleSensorDiagnostic.py
  SinglePendulum/
    PythonMaster_auto.py
    PythonMasterSwingUpExp.py
    swingup_control.py
  DoublePendulum/
    PythonMaster2_auto.py
    PythonMasterMath2.py
    control_matrices2.txt
```

## Change physical measurements

Edit `physical_parameters.py` for arm mass (kg), length and center of mass (m),
inertia (kg m²), cart mass, drag, gravity, sample period and cart travel per
6400 steps. Each arm's `weight_n` is calculated as mass times gravity, in newtons.
`SINGLE_ARM` describes the single-arm setup; `DOUBLE_ARM_1` and `DOUBLE_ARM_2`
describe the double-arm setup. Their existing measurements differ intentionally.
No triple-arm measurements have been assumed; add a measured setup when needed.

Restart scripts after editing configuration. The single controller and swing-up
script calculate their models on startup. For double-arm physical or sample-period
changes, run `PythonMasterMath2.py` to regenerate `control_matrices2.txt` before
running the controller. Run the generator from `Code/DoublePendulum` so it uses
the existing symbolic-model cache. Numeric parameter edits do not require deleting
that cache. Existing matrices have not been regenerated by this reorganization.

Offsets, safety limits and controller tuning remain in their respective scripts.
Legacy scripts and `Archive/` retain their historical embedded measurements and
serial format; they do not use this configuration or the current receiver.
Encoder resolution must remain compatible with the receiver firmware.

## Shared files

- `run_csv_logger.py`: asynchronous CSV writer and single/double column schemas.
- `angle_protocol.py`: framed serial packet reader, validation and diagnostics.
- `angle_packet_fallback.py`: setup sample collection and single-arm prediction.
- `live_offset_keys.py`: nonblocking keyboard offset input.
- `AngleSensorDiagnostic.py`: receiver-only diagnostic for every arm channel.

Run diagnostics from the repository root with
`python3 Code/Global/AngleSensorDiagnostic.py` (motor power off).
Controllers can still be launched directly in Thonny or by their file path;
shared imports resolve relative to the script location, regardless of the terminal's
current directory. CSV run logs stay in each controller's own `run_logs/` folder.
Swing-up control and double-arm matrices stay with the setup that uses them.

## Use this package in a new controller

For a script in `Code/<setup>/`, add the parent `Code` directory to its import path:

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))
from Global.physical_parameters import DOUBLE_ARM_1
from Global.run_csv_logger import RunCsvLogger
from Global.angle_protocol import AnglePacketReader
```

Additional shared helpers belong here; use relative imports between package files.
Importing this package does not open serial devices or start a motor.
